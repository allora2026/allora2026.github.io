Three things to retrieve before AI touches a technical task.

Published November 11, 2026

An approved AI tool should not begin a deployment, incident investigation, or implementation task with a clever blank prompt. It should begin with the context it is allowed to use. The difference is not ceremonial. It decides whether the tool is applying the team’s judgment or merely accelerating a guess.

Yesterday’s runbook may still be useful. The question is whether this task can retrieve the small set of facts that makes it applicable now. Run this diagnostic before the first command, change, or generated patch.

1. Retrieve the permitted source set

Ask: which current documents, runbooks, repository patterns, or prior fixes may this person or tool use for this task? “Everything we have” is not an answer. A useful source set is scoped to the service, environment, customer, project, or team that governs the work.

If finding it requires a scavenger hunt across chat, tickets, and personal recollection, the failure is already visible: the relevant context is not available at the trigger.

2. Retrieve the decision that makes the rule make sense

A standard without its reason invites brittle compliance. Find the architecture decision, incident lesson, or accepted exception that explains the constraint. The aim is not to load an AI tool with an archive. It is to make the reasoning inspectable when the task does not fit the happy path.

This is where a source link earns its keep. A tool can cite the rule; a responsible operator can inspect why it applies.

3. Retrieve the approved return path

Before work starts, decide where a verified outcome goes if it changes the standard. A pull request comment, incident channel, or private chat may contain a useful observation, but none is automatically a reusable lesson. Someone needs a reviewable route back into the governed source material.

That final check keeps the exercise honest. If there is no place for the correction to return, the next task will begin with the same reconstruction—only later and under more pressure.

The test is deliberately small

You do not need a documentation migration to run it. Choose one recurring task this month: a deployment, a production investigation, or an implementation change. Can the responsible person—or an approved AI tool—retrieve the permitted source set, the decision behind the constraint, and the approved route for a reviewed lesson?

The point is not to promise automatic technical judgment. It is to put the right governed context in reach before work begins.
