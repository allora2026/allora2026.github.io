If onboarding needs a narrator, the memory is not ready.

Published November 5, 2026

A senior colleague can rescue a task. They can explain why the obvious folder is wrong, which exception survived the last change, and what “done” really means here. That is generous work. It is also a warning light when it is the only route through a recurring workflow.

The issue is not that people explain things. People should. The issue is making a person’s recollection the permanent interface to the work. It does not scale to the next teammate, the next project, or the next approved AI tool. It leaves everyone else to reconstruct the hidden history at the moment they need to act.

Try the narrator test

Choose one task that a new teammate is expected to perform this month. Before asking anyone to walk them through it, see whether they can find four things:

  1. the outcome the task is meant to produce;
  2. the current source and decision that make the path applicable;
  3. the boundary that says which context belongs with this task; and
  4. the place where a reviewed correction will be available for the next run.

If a capable colleague still has to narrate any of those from memory, do not treat that as a personal failure. Treat it as a design fact: the team has useful knowledge, but it has not yet become a retrievable working surface.

Make the explanation leave a trace

The remedy is not a larger onboarding library. Start with the explanation that repeatedly unlocks the task. Put its source, decision, scope, and review path somewhere the right people can reach. Then let the next real run expose what is missing. A correction that stays in a private chat merely creates a future narrator.

This is why organisational memory has to be governed as well as stored. Usable publicly offers owned workspaces, access boundaries, source-returning retrieval, and solution writeback: enough structure for a team to preserve the route into a task without making every piece of context universally available. The aim is not to replace the experienced colleague. It is to free them from having to be the only interface.

Pick the first task that still begins with “ask someone who knows.” Make the explanation inspectable, scoped, and reviewable. Explore how Usable gives teams and approved AI a governed shared memory.
