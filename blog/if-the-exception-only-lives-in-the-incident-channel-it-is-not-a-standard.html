If the exception only lives in the incident channel, it is not a standard.

Published November 12, 2026

The incident is over. Someone has explained the exception, the workaround has held, and the channel has moved on. That feels like learning. It is not yet a standard.

A standard has to survive the moment that produced it. The next on-call engineer—or an approved AI tool—needs to find the source, understand which boundary it applies inside, and know who can review a change to it. A fast answer buried in chat is evidence. It is not an operating interface.

Close the exception with three questions

  1. What changed? State the rule, exception, or fix in a form the next task can act on. Do not preserve a transcript and call it a procedure.
  2. Where does it apply? Tie it to the service, environment, project, or access boundary that governs it. An exception with no scope becomes accidental folklore.
  3. What supports it? Keep the source decision, incident evidence, or reviewed rationale near enough to inspect. The next person should not have to repeat the archaeology just to know whether the exception still holds.

None of this requires turning every incident into a ceremony. It requires admitting that the channel is optimized for coordination now, not retrieval later. The useful closeout is small: a reviewed update that can be found before the same class of work begins again.

Capture is not clerical work

The writeback is where a technical team decides whether an expensive lesson will compound. Without it, each incident creates a private improvement and a public-looking trail of scrollback. The next task still starts with a hunt.

Usable describes this as a cycle: discover the relevant permitted source, structure the next action, then capture a reviewed lesson. Its workspaces and access boundaries keep the exception with the team or context allowed to use it; source-returning search keeps the rationale inspectable rather than folklore. That is the product-shaped answer to a mundane but recurring failure: important technical knowledge should not depend on remembering the exact channel and week where it was first explained.

Pick one exception from a recent deployment, investigation, or implementation task. Could a new on-call engineer retrieve the applicable source, inspect the reason, and return a reviewed update inside the right boundary? If not, the lesson is still waiting to become a standard.
