What survives the client handover?

Published September 29, 2026

A finished engagement leaves behind two kinds of knowledge. One can make the next piece of work better. The other explains a particular client’s world. Confusing them is how consultancies either throw away hard-won delivery learning or carry context farther than it belongs.

Reusable does not mean portable. A delivery standard can compound; a client’s working context still belongs inside its boundary.

The boundary test

Take one note from a completed engagement and sort it before calling it reusable.

Reusable delivery standard
A method, checklist, decision pattern, or implementation lesson that still makes sense when names, architecture details, commercial terms, and project facts are removed. It tells a future team how to work.
Client-specific context
A project decision, meeting outcome, configuration detail, stakeholder constraint, or source record whose meaning depends on one client. It tells the original team what happened here.

Three questions before the record travels

  1. Would this still be useful if the client name disappeared? If not, it is context, not a general standard.
  2. Does the note contain facts the next team is not entitled to retrieve? If yes, keep it in the client or project boundary.
  3. Can the next reader identify the source and scope? If not, it is not ready to guide another engagement yet.

This is not a classification ceremony. It is the small discipline that prevents a shared template from becoming an accidental permission slip.

Give each record the home it actually needs

Usable is built around this distinction: teams can organise knowledge by workspace, team, customer, or project, then use roles and access boundaries to keep it under the right control. Its public client-work framing names both reusable delivery knowledge and client context; those are related, but they are not the same thing.

Run the test on one completed engagement. Keep the client record where it belongs. Extract the standard only when it survives without borrowing private context. If you need a governed place for both kinds of knowledge, explore Usable.
